# 页面筛选和图片编码覆盖补充

此前“页序”检查和 GT 浏览器切页按钮不等于 DeckRender 参数测试。原 CLI 适配器未转发 pages，示例与真实执行不一致；现已修复 CLI/SDK 参数传递，空白字符串保留为负例输入。

| 范围 | 预期与判定 |
|---|---|
| 各支持的图片路线 × CLI/SDK | 单页筛选；显式 PNG/JPEG/WebP；本地 WebP、Keynote JPEG 明确拒绝 |
| 三页 PDF/PPTX × 本地/云端 × CLI/SDK | 2-3 范围、1,3 非连续、3,1,3 去重升序；输出为原始源页码，JSON pages 为筛选前总数 |
| 同上非法参数 | 0、倒序范围、字母、越界页 4、空白字符串：usage_error，无成功产物 |
| PDF 输出 | 有效页码筛选被明确拒绝，不假定 PDF passthrough 会裁页 |
| 成功结果的 R09 | 每个参数成功案例绑定独立质量案例；输出序号、实际 page、预期源页和源哈希关联对应 GT 图 |
| 图片编码 | 用 Pillow 检查实际编码，不能仅看扩展名；WebP 的额外转换路线绑定冻结的 plan.ts |

GT 工作台显式展示“页面筛选与图片编码测试点”；coverage 单列参数案例。参考图按源文件和页码复用，不为每个接口或参数重复准备 GT。新增 128 个参数契约案例和 74 个成功质量案例；基础 54 格矩阵不受变体增减影响。所有新题为 draft，0 个答案获批。

Evaluator 升为 v4，保留历史 v3 规则；比较不应把 evaluator 变化归因于产品退化。自测包括乱序、重复、重编号、漏筛选、伪扩展名、损坏图片、CLI/SDK 参数透传和错页 GT 绑定。模拟结果只用于框架测试。

未覆盖：`--page` 别名、profile/config 的软参数与优先级、参数组合全部交叉、视频筛选拒绝专项、加密/损坏/超大文档、真实动画音视频的完整时序。本轮未新增 Hugging Face 数据；现有三页标识样本可独立支持这些参数边界。GT 仍需人工确认；第三方导出仅用于候选准备，不要求强制交叉验证。

没有运行真实质量或云端实验。deck-benchmark/SKILL.md 要求 “Stop before the quality run until the user approves or edits the draft.” 代码实现和自测完成不代替答案审核。
